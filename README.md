# Арена переговоров — интерфейс SPA

Адаптивный интерфейс на **React + TypeScript + React Router + CSS**, собранный по макету `arena_design (1).pdf` и согласованным изменениям. Сборщик — Vite. Реализованы 12 типов экранов, клиентские переходы и визуальные заглушки.

**Это этап интерфейса.** Авторизация, создание аккаунтов, прохождение переговоров, расчёт оценок, сохранение и публикация сценариев не подключены. Нет запросов к серверу приложения, базе данных или нейросети. Все сценарии, история и баллы — демонстрационные данные. Запуск Vite нужен только для выдачи файлов браузеру.

## Быстрый запуск

Понадобится Node.js **22.12+** (проверено на 24.19.0) и npm. Распакуйте ZIP целиком **в новую пустую папку**, затем откройте терминал **в папке `arena-negotiations`, где находится `package.json`**.

```bash
npm ci
npm run dev
```

Откройте **http://127.0.0.1:5173**. Для остановки нажмите `Ctrl+C`.

На Windows в PowerShell можно использовать:

```powershell
cd путь\к\arena-negotiations
npm.cmd ci
npm.cmd run dev
```

Зависимости загружаются при `npm ci`. Шрифт и изображения входят в проект: во время просмотра приложение не обращается к внешним сервисам. Переменные окружения, ключи API и Ollama не нужны.

Если появляется `Missing script: dev`, проверьте текущую папку: команда `npm run` должна показывать `dev`, `build`, `preview`, `typecheck` и `test:ui`. Не запускайте команды из внешней папки, в которую распакован архив, если `package.json` лежит уровнем ниже.

## Если раньше появлялся белый экран

Сообщение `scenarios.js does not provide an export named findScenario` означает, что браузер загрузил другой модуль вместо актуального `src/data/scenarios.ts`. Это воспроизводится при распаковке React-версии поверх старого JavaScript-проекта: старый `scenarios.js` остаётся рядом, а импорт без расширения выбирает его.

В версии **0.2.1** относительные импорты исходников явно указывают `.ts` или `.tsx`. Одноимённые старые `.js` больше не подменяют эти модули. Автоматического удаления файлов нет.

Для обновления сохраните свою текущую папку, распакуйте новый архив отдельно, остановите старый сервер через `Ctrl+C` и выполните `npm ci`, затем `npm run dev` в новой папке. Откройте адрес из терминала и обновите страницу через `Ctrl+F5`. Свои изменения переносите выборочно, не копируя старый `src/` целиком поверх нового.

## Сборка и проверка

```bash
npm run typecheck
npm run build
npm run preview
```

Production-сборка создаётся в `dist/`. Предпросмотр: **http://127.0.0.1:4173**. `index.html` не следует открывать двойным щелчком: для SPA нужен HTTP-сервер с возвратом `index.html` на клиентские маршруты.

Дополнительные команды:

| Команда                | Назначение                                       |
| ---------------------- | ------------------------------------------------ |
| `npm run dev`          | Разработка с автоматическим обновлением страницы |
| `npm run build`        | Проверка TypeScript и production-сборка          |
| `npm run preview`      | Локальная проверка готовой сборки                |
| `npm run typecheck`    | Проверка типов без сборки                        |
| `npm run format`       | Единое форматирование исходников                 |
| `npm run format:check` | Проверка форматирования                          |
| `npm run test:ui`      | Браузерные проверки Playwright                   |

Для запуска браузерных проверок после установки зависимостей:

```bash
npx playwright install chromium
npm run build
npm run test:ui
```

Тесты сами запускают сервер предпросмотра. Необязательная переменная `PW_EXECUTABLE_PATH` позволяет указать уже установленный Chromium в среде автоматизации; для обычного запуска она не нужна.

Чтобы открыть интерфейс с телефона в своей локальной сети, можно запустить `npm run dev -- --host 0.0.0.0` и открыть адрес компьютера с портом `5173`. По умолчанию сервер доступен только на текущем компьютере. Если порт занят, завершите предыдущий процесс или укажите другой через `--port`.

## Страницы и маршруты

| Маршрут                         | Содержимое                                                            |
| ------------------------------- | --------------------------------------------------------------------- |
| `/`                             | Главная: вводный блок и карточки сценариев                            |
| `/scenarios`                    | Каталог с поиском, фильтрами и состоянием пустой выдачи               |
| `/register`                     | Регистрация: поля, подтверждение пароля, демонстрационное уведомление |
| `/login`                        | Вход: поля и уведомление о заглушке                                   |
| `/profile`                      | Демонстрационный профиль, показатели и история практики               |
| `/scenarios/:scenarioId`        | Превью: контекст, задача, совет и собеседник                          |
| `/scenarios/:scenarioId/play`   | Макет диалога с выбором одной реплики                                 |
| `/scenarios/:scenarioId/result` | Заранее подготовленный пример разбора                                 |
| `/editor`                       | Пример списка авторских сценариев                                     |
| `/editor/:scenarioId`           | Редактор: вкладки описания и диалога                                  |
| `/404`                          | Экран ошибки 404                                                      |
| `/500`                          | Демонстрационный экран ошибки 500                                     |
| Любой неизвестный адрес         | Экран 404                                                             |

Доступные `scenarioId`: `new-deadline`, `feedback`, `terms`. Например: `/scenarios/new-deadline/play` и `/editor/new-deadline`.

Неизвестный идентификатор сценария тоже открывает 404. `/500` — отдельная страница для просмотра макета; она не создаёт реальную серверную ошибку. При статической SPA-раздаче HTTP-статус документа остаётся 200, даже когда клиент показывает экран 404.

## Что работает

- Переходы React Router без полной перезагрузки, прямое открытие URL, история «Назад/Вперёд».
- Поиск сценария по названию, описанию, категории и навыку; совместные фильтры категории и сложности; сброс. Фильтры отражаются в URL и сохраняются при возврате из превью.
- Мобильное меню с закрытием по Escape и после перехода.
- Подписи полей, состояния фокуса, переход к содержимому с клавиатуры, управление вкладками стрелками, модальное окно с возвратом фокуса.
- Проверка обязательных полей, формата почты и повторного пароля; переключение видимости пароля. Это только проверки интерфейса.
- Выбор реплики в макете диалога и переход к **примеру** разбора.
- Переключение вопросов и вкладок редактора, изменение видимых полей в памяти текущего экрана.

## Что осталось заглушками

- Регистрация и вход: показывается уведомление, аккаунт не создаётся, вход не выполняется. После демонстрационной отправки поля очищаются. Приложение не сохраняет пароли.
- Изменение профиля: поля доступны для проверки вёрстки, сохранение не выполняется.
- Переговоры: нажатие «Ответить» показывает уведомление; реакция персонажа, переходы ветвей и оценки не вычисляются.
- Результаты и история: статические примеры, не связанные с выбранными пользователем репликами.
- Редактор: создание/удаление вопросов и ответов, сохранение и публикация показывают заглушку. Изменения полей исчезают при уходе со страницы. «Предпросмотр» открывает исходный пример.
- Отзывы, условия использования и политика конфиденциальности: информационные заглушки.

В проекте нет поддельного состояния «пользователь вошёл», сохранения в `localStorage` и имитации ответа нейросети.

## Где менять интерфейс

- Цвета, размеры и общие переменные: `src/styles/tokens.css`.
- Глобальная типографика и формы: `src/styles/base.css`.
- Общие компоненты: `src/styles/components.css`.
- Стили конкретных экранов: `src/styles/pages.css`.
- Перестроение под ширину экрана: `src/styles/responsive.css`.
- Демонстрационные сценарии, персонажи, реплики, примеры разбора: `src/data/scenarios.ts`.
- Пример профиля и истории: `src/data/profile.ts`.
- Маршруты: `src/routes/AppRoutes.tsx`.

## Почему этот стек

React отвечает за компоненты; TypeScript — за типы данных и интерфейсов; React Router — за клиентскую навигацию; Vite — за разработку и сборку. Стили написаны на обычном CSS. Шрифт Manrope поставляется локально через Fontsource.

TanStack Query и Redux пока не добавлены: сетевых запросов нет, а состояние ограничено формами, фильтрами, вкладками и уведомлением. Фильтры хранятся в URL, состояние полей — в React, уведомление — в небольшом контексте. Зависимости зафиксированы в `package-lock.json`.

Основы настройки: [React Router — декларативный режим](https://reactrouter.com/start/declarative/installation), [Vite — руководство](https://vite.dev/guide/).

## Приоритетные изменения из задания

- В шапке нет «Как это работает».
- На главной удалены указанная подпись под кнопками, вторая кнопка, зелёный блок «Три шага…» и заключительный текст. Текст у иллюстрации вынесен за пределы изображения.
- В каталоге нет декоративной зелёной стопки; «Сбросить» — контрастная кнопка с обводкой.
- На регистрации левая часть заменена отдельной типографической композицией с репликами; фотография не перекрывает текст.
- В профиле нет левой навигации и секции сильных сторон. «Разбор» оформлен отдельной кнопкой со значками и открывает соответствующий пример.
- В настольном превью карточка собеседника растягивается до нижней границы совета.
- В 404/500 основной акцент — крупный код; в содержимом одна кнопка «На главную». Лишние подписи и вторые действия удалены.

## Размещение SPA

В разработке и предпросмотре Vite сам отдаёт `index.html` для клиентских маршрутов. При размещении загрузите **содержимое `dist/`**, а не `src/`.

В комплекте:

- `public/_redirects` → копируется в `dist/_redirects`: правило для Netlify-совместимого хостинга.
- `vercel.json`: сборка Vite, каталог `dist` и перенаправление клиентских маршрутов.

Пример для Nginx:

```nginx
server {
    listen 80;
    root /var/www/arena/dist;
    index index.html;

    location /assets/ {
        try_files $uri =404;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

Текущая конфигурация рассчитана на корень домена. Для размещения в подпапке нужно согласованно задать `base` в Vite, `basename` в `BrowserRouter`, пути публичных ресурсов и правило возврата `index.html`.

Проверка проведена в Chromium на Linux. Реальные Safari/iOS, Firefox, запуск на Windows и размещение на хостинге в этой среде не проверялись. Подробнее: `docs/VERIFICATION.md`.
