# HTTP API

Базовый путь `/api`. JSON в UTF-8. Успешные запросы чтения и большинства изменений — 200, регистрация и создание черновика — 201, выход и архивирование — 204.

Браузер использует HttpOnly cookie `arena_session`, `SameSite=Lax`, срок 7 суток. В базе хранится SHA-256 токена. Пароли хешируются `scrypt` с индивидуальной случайной солью. HTTPS-вариант включается через `COOKIE_SECURE=true`.

Все изменяющие запросы требуют:

```http
Content-Type: application/json
X-Arena-Request: 1
```

Если присутствует `Origin`, он должен входить в `APP_ORIGIN`. CORS для сторонних сайтов не включён. В dev Vite проксирует `/api` на Node; в сборке Node раздаёт API и SPA с одного адреса.

## Маршруты

| Метод и путь                        | Доступ                       | Результат                                                                        |
| ----------------------------------- | ---------------------------- | -------------------------------------------------------------------------------- |
| `GET /health`                       | Все                          | Проверяет соединение с PostgreSQL                                                |
| `GET /auth/me`                      | Все                          | Текущий `User` либо `null`                                                       |
| `POST /auth/register`               | Все                          | `{ name, email, password }` → аккаунт и cookie                                   |
| `POST /auth/login`                  | Все                          | `{ email, password }` → аккаунт и cookie                                         |
| `POST /auth/logout`                 | Все                          | Удаляет текущую серверную сессию                                                 |
| `PATCH /me`                         | Аккаунт                      | `{ name, email }` → сохранённый профиль                                          |
| `GET /me/history?limit=20&offset=0` | Аккаунт                      | История и агрегаты только своего пользователя                                    |
| `GET /scenarios`                    | Все                          | Опубликованные неархивные `{ preview, definition }[]`                            |
| `GET /attempts/current`             | Аккаунт                      | Текущие попытки с их версиями и отзывами                                         |
| `GET /attempts/:id`                 | Владелец попытки             | Полный `AttemptDetail`, включая старые попытки                                   |
| `POST /scenarios/:id/attempts`      | Аккаунт                      | `{}` → продолжение существующей или новая попытка                                |
| `POST /scenarios/:id/attempts`      | Аккаунт                      | `{ restart:true, expectedAttemptId }` → новая попытка, старая остаётся в истории |
| `POST /attempts/:id/answers`        | Владелец попытки             | `{ nodeId, answerId, expectedAnswers }` → подтверждённое состояние               |
| `PUT /attempts/:id/feedback`        | Владелец завершённой попытки | `{ helpful, comment }` → созданный/обновлённый отзыв                             |
| `GET /editor`                       | Аккаунт                      | Собственные сценарии и черновики                                                 |
| `POST /editor`                      | Аккаунт                      | `{ sourceId }` → собственная копия опубликованного сценария, `{ id }`            |
| `GET /editor/:id`                   | Владелец сценария            | `{ preview, definition, revision, publishedVersion }`                            |
| `PUT /editor/:id`                   | Владелец сценария            | `{ preview, definition, revision }` → новая `revision`                           |
| `POST /editor/:id/publish`          | Владелец сценария            | `{ revision }` → новая неизменяемая версия и новая редакция черновика            |
| `POST /editor/:id/archive`          | Владелец сценария            | Убирает карточку из публичного каталога                                          |

Каждый опубликованный сценарий содержит непустой канонический `definition: MakerDefinition`. Preview-only публикации больше не создаются.

## Ответ на подтверждение реплики

```json
{
  "nodeId": "q1",
  "answerId": "q1-a1",
  "expectedAnswers": 0
}
```

Сервер возвращает:

```typescript
interface AttemptDetail {
  attempt: ScenarioAttempt;
  definition: MakerDefinition;
  feedback?: Feedback;
  isCurrent: boolean;
  abandonedAt: string | null;
}
```

`definition` — снимок, привязанный к попытке, а не последняя публикация сценария. Клиент строит разбор именно по нему. Передавать `penalties`, `endingId`, `userId` и другие поля вне схемы нельзя: лишние поля отклоняются.

## История

```typescript
{
  total: number;       // все попытки пользователя
  completed: number;   // завершённые попытки
  penalties: number;   // сумма штрафов завершённых попыток
  rows: HistoryRow[];
}
```

Пагинация: `limit` от 1 до 100, `offset` от 0 до 1 000 000. Длительность из карточки сценария — текстовая оценка, не измеренное время пользователя.

## Ошибки

```json
{ "error": "Проверьте введённые данные", "details": [{ "field": "email", "message": "..." }] }
```

| Код | Значение                                                            |
| --- | ------------------------------------------------------------------- |
| 400 | Невалидный JSON                                                     |
| 401 | Требуется вход или неверные учётные данные                          |
| 403 | Не прошла проверка заголовка/Origin                                 |
| 404 | Нет ресурса или нет доступа к чужому ресурсу                        |
| 409 | Конфликт попытки/черновика, повторная почта, недопустимое состояние |
| 413 | Размер тела больше 2 MiB                                            |
| 415 | Не `application/json`                                               |
| 422 | Некорректные поля или граф сценария                                 |
| 429 | Слишком много попыток входа/регистрации                             |
| 503 | Временная ошибка сервера/БД                                         |

После 409 при ответе UI повторно получает актуальное состояние. После сбоя сети вопрос не меняется: отправку можно повторить. Если предыдущий ответ уже записался и потерялся только HTTP-ответ, точный повтор подтверждается без второй записи истории.

Публикация блокирует строку сценария и создаёт версию атомарно. Два параллельных сохранения одного черновика с одинаковой `revision` не перетрут друг друга: одно завершится 409.

## Границы текущей реализации

- Редактировать, публиковать, архивировать и удалять сценарии может только администратор-владелец. Пользователи без роли администратора не получают доступа к редактору.
- Смена email не требует подтверждения почты. Восстановление пароля и смена пароля не реализованы.
- Ограничение запросов авторизации действует в памяти одного процесса (30 попыток за 15 минут на IP). Для нескольких экземпляров нужен общий ограничитель.
- Каталог и список текущих попыток рассчитаны на небольшой проект; пагинация реализована для истории. Для большого каталога потребуется серверная фильтрация и постраничная загрузка.
- Снимки графов доступны клиенту для отображения. Это учебный тренажёр, а не система закрытого экзамена с сокрытием ответов.
- `auth_sessions` с истёкшим сроком не авторизуют пользователя; SQL для их очистки приведён в `DATABASE.md`.

## Дополнение 0.4.0: динамический maker

- `POST /api/editor`: прежнее `{ "sourceId": "terms" }` создаёт копию; новое `{ "title": "Переговоры о зарплате" }` создаёт пустой черновик v2. Ответ: `{ "id": "custom-..." }`.
- `GET /api/editor/:id`: возвращает канонические `preview`, `definition`, `editor`, `revision`, `publishedVersion`, `archivedAt`, `hasUnpublishedChanges`. Старые документы при чтении нормализуются серверным compatibility-layer.
- `PUT /api/editor/:id`: `preview`, `definition`, `editor`, `revision`. Формат v2 — `features/maker/model/types.ts`. Незавершённый граф можно сохранить. Если старый клиент не прислал editor, его предыдущее значение в базе сохраняется. Координаты, масштаб и примеры проходят проверку типов и ограничений размера.
- `POST /api/editor/:id/publish`: прежнее `{ "revision": 2 }`; для v2 сервер повторяет проверку графа. При 422 поле `details` содержит `{ severity, code, message, nodeId?, reactionId? }`. Публикация сохраняет v2, но не editor.
- `GET /api/scenarios` и ответы с попытками возвращают тот же канонический `MakerDefinition`, который был опубликован. `editor` в опубликованную версию не входит; `intent` и `examples` остаются частью графа для будущего AI.
- Тестовый режим maker локален: он не вызывает endpoints создания попыток и не меняет базу.

Версия definition (`metadata.version`) относится к публикации; revision — к черновику; schemaVersion: 2 — к формату графа. Это три разных счётчика/идентификатора. Начатые попытки остаются на прежней опубликованной версии.

## Изменения редактора

- `GET /api/editor` и `GET /api/editor/:id` возвращают `hasUnpublishedChanges`: сравнение содержимого черновика с последним опубликованным снимком, без координат и масштаба `editor`. Сохранение новой редакции не публикует её. `PUT /api/editor/:id` возвращает `{ revision, hasUnpublishedChanges }`.
- `DELETE /api/editor/:id` доступен только администратору-владельцу, ответ `204`. Сценарий получает `deleted_at`, исчезает из каталога и редактора; его нельзя копировать, публиковать или начинать новые попытки. Уже созданные попытки и их снимки сохраняются. Для удаления требуется миграция `003_scenario_deletion.sql`.
- Необязательное `preview.coverImage`: `{ src: "data:image/png;base64,...", alt: "Описание" }`; разрешены PNG, JPEG и WebP, до 710 000 символов в `src` и 250 в `alt`. Клиент ограничивает файл 512 КБ. Общий лимит JSON-запроса остаётся 2 МБ. SVG и произвольные URL не принимаются.

## Обращения с публичной страницы

- `POST /api/contact`: без авторизации, с обычными проверками источника и заголовком `X-Arena-Request: 1`. Тело: `{ requestId, topic, email, message }`; `requestId` — UUID, тема — `question`, `issue`, `idea` или `partnership`, сообщение — 20–3000 символов. Успех: HTTP 201 и `{ id }`. Повтор с тем же идентификатором не создаёт вторую запись. Лимит — 5 запросов с IP за 15 минут, затем HTTP 429 с `Retry-After`.
- `GET /api/admin/messages?offset=0`: только для администраторов; ответ `{ messages, hasMore }`. Страница содержит до 30 сообщений, новые сверху. Отрицательный или нецелый offset отклоняется с 422.
- Таблица `contact_messages` создаётся миграцией `005_contact_messages.sql` и не связана с отзывами о прохождении сценариев. Письма сайт не отправляет: ссылка «Ответить» открывает почтовую программу.

## Геймификация

- `GET /api/me/gamification` — прогресс текущего пользователя: общий XP/уровень, недельная цель, навыки, достижения и мастерство сценариев.
- Завершённый `POST /api/attempts/:id/answers` дополнительно возвращает `reward` в `AttemptDetail`. В награде есть итоговый XP, XP навыка, 1–3 звезды, причина коэффициента повтора, детализация расчёта и достижения, открытые именно этой попыткой.
- `GET /api/me/history` для завершённых попыток добавляет `xpEarned` и `masteryStars`.
- `GET /api/admin/achievements` — список правил достижений и статистика получения; только администратор.
- `POST /api/admin/achievements` — создать достижение из одного из разрешённых типов условий.
- `PATCH /api/admin/achievements/:id` — изменить правило или перевести его в архив/вернуть из архива. Физического удаления нет: уже полученные достижения сохраняются.

Повторное начисление одной попытки блокируется первичным ключом `attempt_rewards.attempt_id`. Первое прохождение сценария и новая концовка дают 100% рассчитанной награды; повтор уже открытой концовки — 35%.

### Отзывы о сценариях

`GET /api/admin/reviews?offset=0&scenarioId=terms&helpful=yes` — вкладка «Отзывы» в админке.

- Только администраторы: главный видит все отзывы, обычный — отзывы о сценариях, которыми он владеет. Это ограничение применяется на сервере к списку, счётчикам и вариантам фильтра.
- Необязательные параметры: `offset` (целое от 0 до 1 000 000), `scenarioId`, `helpful` (`yes` / `no`). Без фильтров возвращаются все доступные отзывы, по 30 на страницу.
- Ответ: `{ reviews, total, helpfulCount, hasMore, scenarios }`. Счётчики учитывают активные фильтры. `scenarios` содержит доступные сценарии с отзывами независимо от фильтров.
- Запись содержит `attemptId`, `scenarioId`, `scenarioTitle`, `scenarioVersion`, `authorName`, `helpful`, `comment`, `createdAt`, `updatedAt`, `archived`, `deleted`. Email и другие приватные данные участника не передаются.
- Название и версия в карточке относятся к пройденной версии. В фильтре отображается текущее название. Отзывы архивных и удалённых сценариев доступны с соответствующей пометкой. После передачи сценария другому владельцу права просмотра переходят вместе с ним.
- Новые отзывы идут первыми: `created_at DESC, attempt_id DESC`. Повторная отправка через существующий `PUT /api/attempts/:id/feedback` обновляет отзыв той же попытки, не создаёт дубликат и не меняет дату первоначального создания.
