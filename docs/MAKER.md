# Динамический maker — MVP 0.4.0

Реализованы все четыре этапа предложенного плана. Макет из `arena_dynamic_maker_design(1).pdf` использован для структуры рабочего пространства, цветов, карточек, правой панели и тестового окна. Условные блоки, эффекты и AI из расширенного дизайн-концепта не входят в этот MVP.

## Этап 1. Модель и совместимость

`src/features/maker/model/types.ts` — каноническая модель новых сценариев, `schemaVersion: 2`.

```ts
{
  definition: {
    schemaVersion: 2,
    metadata: { /* данные каталога */ },
    startNodeId: 'salary_question',
    characters: [],
    stages: [],
    nodes: [{
      id: 'salary_question',
      title: 'Ожидания',
      characterId: 'hr',
      stageId: 'negotiation',
      text: 'Какую зарплату вы ожидаете?',
      reactions: [{
        id: 'reaction_salary_offer',
        intent: 'salary_offer',
        label: 'Назвать сумму',
        examples: ['Рассчитываю на 200 тысяч'],
        evaluation: {
          grade: 'strong',
          penalty: 0,
          feedback: 'Вы называете конкретный ориентир и оставляете пространство для обсуждения.'
        },
        nextNodeId: 'salary_discussion'
      }]
    }],
    endings: [],
    settings: { allowRestart: true, collectFeedback: true, feedbackMode: 'summary' }
  },
  editor: {
    positions: {
      salary_question: { x: 420, y: 180 }
    },
    viewport: { x: 0, y: 0, zoom: 0.8 }
  }
}
```

Это фрагмент формата, не готовый исполняемый сценарий. В полном документе также остаётся `preview`, совместимый с существующим каталогом. Перед публикацией сервер строит его из `definition`. `preview` не управляет переходами.

- У реакции ровно один `nextNodeId` или `endingId`. В незавершённом черновике оба могут отсутствовать, но такой граф нельзя запустить или опубликовать.
- `intent` уникален внутри одной реплики. Один смысл может повторяться у разных персонажей и в разных местах разговора.
- `label` и `examples` редактируются независимо от intent. Переименование кнопки не меняет маршрут.
- ID блоков и реакций не зависят от текста. При дублировании создаются новые ID реакций, а их смыслы сохраняются.
- `stageId` необязателен. Этап — группировка для человека, не условие перехода.
- Двигатель не читает `editor`. Перетаскивание меняет только координаты.

`adapter.ts` работает только с текущим `MakerDefinition`: создаёт пустой граф, строит каталоговый `preview` и формирует maker-черновик. Старые `speakerId / answers / next`, `reaction.legacy`, `settings.legacyFailure` и preview-only документы разбираются отдельно в compatibility-layer и сразу переводятся в текущую модель. В runtime они не используются. Варианты реплики по предыдущей реакции остаются в `textVariants`.

В `scenario_versions.definition` и `scenario_drafts.definition` хранится один канонический граф. Maker, сервер и проигрыватель используют его напрямую — отдельной runtime-проекции больше нет. Старые записи БД можно один раз привести к текущей сериализации командой `npm run db:normalize-scenarios`; импорт старых JSON остаётся совместимым.

## Этап 2. Полотно

`ui/ScenarioCanvas.tsx` использует `@xyflow/react` 12.11.6: перемещение карточек, zoom/pan, точки входа и выходы реакций, стрелки, мини-карта, fit view. Карточки созданы под стиль проекта, не стандартные прямоугольники библиотеки. Поля редактора открываются при выборе карточки, реакции или стрелки. Начальная автораскладка вычисляется в `model/commands.ts`; ручные координаты имеют приоритет.

Размер полотна адаптируется к экрану. Ширина Inspector меняется перетаскиванием его левой границы; с клавиатуры доступны стрелки, Home и End. Выбранная ширина запоминается в браузере. Изменение ширины не сбрасывает масштаб полотна. На узком экране структура и Inspector открываются поверх полотна. Выход реакции автоматически переносится влево, если её целевой блок находится слева. Вход стартового блока скрыт.

## Этап 3. Редактирование

- Создание пустого сценария или копии опубликованного.
- Создание реплик, реакций и трёх типов финалов.
- Перетаскивание точки реакции на существующий блок.
- Перетаскивание точки в пустое место: меню «Новая реплика / Новый финал / Отмена». После создания переход уже связан, поле текста получает фокус.
- Назначение или снятие перехода в Inspector; новый переход заменяет старый, не создавая двух исходящих связей одной реакции.
- Редактирование intent и примеров фраз.
- Персонажи, этапы, описание, стартовая реплика, настройки повторного прохождения и отзывов. Для каждой реакции можно вручную задать качество ответа, штраф и пояснение; сценарий выбирает режим показа оценки: сразу, в итоговом разборе или скрыто.
- Дублирование, удаление, очистка входящих связей и связанных вариантов реплики. Удаление старта оставляет явную ошибку, а не выбирает новый старт незаметно.
- Undo/redo последних 50 действий, включая Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z и Ctrl/Cmd+Y. Ввод в одном поле до потери фокуса объединяется в один шаг; перемещение блока, добавление и удаление — отдельные шаги. Масштаб и панорамирование в историю отмены не входят. История отмены очищается при обновлении страницы.
- Ручное сохранение в PostgreSQL с optimistic locking по `revision`. При 409 изменения остаются в интерфейсе. В «Настройках» доступны экспорт и импорт переносимого `arena-scenario` JSON; импорт сохраняет ID текущего сценария и попадает в undo/redo как одно действие.
- Несохранённые поля, граф, настройки, превью и координаты сразу записываются в `sessionStorage`, отдельно для пользователя и сценария. После обновления восстанавливаются в той же вкладке. Новая вкладка открывает серверный черновик; перед закрытием вкладки следует сохранить его на сервер. При изменившейся серверной редакции локальная копия сохраняется, перезапись блокируется, доступны экспорт и загрузка серверной версии. Ошибка хранилища показывается пользователю.
- В разделе «Основное» можно загрузить PNG, JPG или WebP до 512 КБ, добавить описание для экранного диктора и удалить картинку. `preview.coverImage` содержит `src` (data URL) и `alt`. Превью публикуется вместе со сценарием.
- Статус «Черновик v2 · опубликовано v1» означает, что пользователям доступна только первая версия. Координаты редактора на статус публикации не влияют.
- Удаление в списке скрывает сценарий из каталога и редактирования, сохраняя опубликованные снимки и историю попыток.

При копировании реплики её исходящие переходы сохраняются. У новой копии нет входящих связей: соедините её вручную. Это также отражается предупреждением о недостижимости.

## Этап 4. Проверка и тест

`model/validation.ts` — общая проверка для UI, движка и публикации на сервере. Проверяются старт, персонажи, тексты, реакции, уникальность ID, формат и однозначность intent, существование обеих разновидностей переходов, финалы, сохранённые варианты реплик и настройки оценки. Недостижимые блоки помечаются предупреждениями. Цикл с выходом допустим, замкнутая ветка без пути к финалу — ошибка. Повторное прохождение ограничено 500 шагами одной попытки; при достижении лимита можно начать заново.

Ошибка выделяет карточку красным. Недостижимый блок имеет жёлтую точку. Клик в списке проверок выбирает блок и центрирует полотно. Предупреждения не запрещают публикацию, ошибки запрещают.

`TestScenarioDrawer` запускает снимок текущего черновика без API попыток, публикации и записи истории. Закрыть тест можно кнопкой, Escape или кликом по затемнению за пределами панели; фокус возвращается к кнопке тестирования. Реплики и финалы используют тот же детерминированный движок, что и настоящее прохождение. Если для сценария включено автоматическое завершение по штрафам, тестовый режим учитывает его. В остальных сценариях итог определяется связями графа.

## Подключение AI позже

`compileMaker` создаёт снимок сценария; `submitIntent(engine, attempt, expectedNodeId, intent, now)` однозначно находит реакцию текущей реплики и передаёт её в общий движок. Неизвестный intent отклоняется, другой узел и завершённая попытка также отклоняются. Кнопки уже используют этот вход.

Будущий классификатор получает только кандидаты текущего узла (`intent`, `label`, `examples`), возвращает один intent либо запрос уточнения. После него вызывается тот же `submitIntent`. Переписывать сценарий или координаты не требуется. Для настоящего AI ещё понадобится серверный endpoint интерпретации, проверка принадлежности попытки и обработка неуверенного распознавания. В текущей версии AI-запросов нет.

## Хранение и запуск

Миграция `002_scenario_editor.sql` добавляет `scenario_drafts.editor jsonb`. Миграция `003_scenario_deletion.sql` добавляет `scenarios.deleted_at`; перед запуском обновлённого сервера выполните `npm run db:migrate`. Опубликованные версии и старые попытки не меняются. Координаты не попадают в `scenario_versions` и не нужны проигрывателю.

Существующая база: `npm ci`, `npm run db:migrate`, `npm run dev`. Новая база: сначала настройка `.env` и `npm run db:setup` из README. Нужен Node.js 22.12+.

Ограничения формата: до 500 реплик, 100 финалов, 30 реакций на реплику, 100 примеров на реакцию; API принимает документ до 2 МБ. Совместного редактирования, автоматического сохранения на сервер, условных блоков, переменных, динамических штрафов, patience, BATNA и генерации AI нет.

Технические ссылки: [создание блока при переносе связи](https://reactflow.dev/examples/nodes/add-node-on-edge-drop), [обновление handles](https://reactflow.dev/api-reference/hooks/use-update-node-internals).
