| Браузерные тесты Playwright | Все 9 сценариев прошли; два тестовых селектора уточнены и соответствующие тесты повторно выполнены |
| Мобильный экран             | Проверен скриншот диалога при ширине 390 px; горизонтального переполнения нет                      |

## API и SQL

- Применение миграции, повторный запуск миграций и seed.
- Импорт трёх исходных карточек; 11 вопросов исполняемого графа не потеряны.
- Регистрация, нормализация email, уникальность, хеш пароля, HttpOnly cookie.
- Чтение и изменение своего профиля, выход и повторный вход.
- Проверки обязательного заголовка запроса и Origin.
- Изоляция попыток, отзывов и черновиков между пользователями.
- Отказ создания реальной попытки для демонстрационного макета.
- Повторное начало возвращает текущую попытку; новый запуск сохраняет старую в истории.
- Два HTTP-запроса с разными ответами не добавляют два перехода на один вопрос.
- Точный повтор уже записанного ответа не дублирует историю.
- Невалидный ответ и переданные клиентом штрафы не меняют состояние.
- Завершение, сохранение и редактирование отзыва, агрегаты истории.
- Сохранение черновика, конфликт редакций, публикация.
- Вторая публикация не меняет снимок уже начатой попытки.
- SQL-триггер отклоняет UPDATE опубликованной версии.
- Циклический граф можно сохранить как черновик, но нельзя опубликовать.
- Архивирование сохраняет историю и убирает карточку из каталога.

## Интерфейс

- Прямые переходы по страницам и отсутствие переполнения на 390 и 1440 px.
- Фильтры каталога, пустая выдача и переходы SPA без перезагрузки документа.
- Регистрация через форму, несовпадение паролей, изменение профиля, выход и вход.
- Создание копии в редакторе, сохранение, перезагрузка, публикация и запуск изменённого сценария.
- Полный диалог, перезагрузка на середине, сохранение/выход, результат, отзыв и новая попытка.
- Открытие старого разбора из профиля после перезапуска.
- Ошибка ответа API: вопрос остаётся прежним; повторное сохранение проходит один раз.
- Гостевой доступ к каталогу и демонстрации; вход обязателен для сохраняемого прохождения.

## Ограничения выполненной проверки

В среде разработки не удалось запустить обычный PostgreSQL daemon. SQL и маршруты проверены на **PGlite**, использующем PostgreSQL в WebAssembly. Браузерные тесты запускались против того же API с тестовым PGlite-адаптером; боевой код использует `pg.Pool`.

PGlite-адаптер находится только в `tests/support/pglite.ts`. Он сериализует операции одного встроенного движка. Поэтому тест двух запросов проверяет HTTP-контракт и отсутствие повторной записи, но **не подтверждает конкурентные блокировки независимых PostgreSQL-соединений**. Также здесь не проверены TCP-подключение к штатному серверу, SCRAM-аутентификация, права ролей, TLS, Docker Desktop и запуск команд на Windows.

Для полноценной проверки предусмотрен `npm run test:api` с `TEST_DATABASE_URL`. Он использует настоящий `pg.Pool` с несколькими соединениями и ту же последовательность проверок. Инструкция — в корневом README. Docker Compose предоставлен как конфигурация запуска; Docker в среде проверки отсутствует.

Проверка не является нагрузочным тестом или аудитом сервиса перед публичным размещением.
