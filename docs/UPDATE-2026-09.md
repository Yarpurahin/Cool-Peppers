# Обновление интерфейса, аккаунтов и обработки ошибок

## Применение

Из корня проекта, для версии `Cool-Peppers-maker-fixes-v0.4.8.zip`:

```bash
git apply --check cool-peppers-improvements-v0.4.8.patch
git apply cool-peppers-improvements-v0.4.8.patch
npm run db:setup
npm run build
```

`git apply` меняет рабочие файлы и не создаёт коммит. Сервер нужно перезапустить.
`db:setup` применяет новую миграцию `004_accounts_and_retired_demos.sql` и выполняет seed.
Ранее применённые миграции не изменены.

## Поведение

- Удалён счётчик `01 / 03` у главной иллюстрации. При ошибке загрузки появляется адаптивная композиция с репликами и подписью, сохраняющая размер блока.
- У всех страниц общий попап сетевых ошибок: анимация появления и закрытия, один экземпляр на экране, повторный показ после новой неудачной попытки. Отмена запроса при уходе со страницы не считается ошибкой соединения.
- HTTP 500 при действии показывает уведомление; поля и выбранный ответ остаются на месте. Неожиданная серверная ошибка возвращает 500 без внутренних подробностей; ошибки соединения с БД — 503. Ошибка загрузки необходимых данных отличается от отсутствующего ресурса. Ошибка отрисовки получает экран 500.
- Кнопки выхода со страниц 404 и 500 заменяют ошибочную запись в истории. После выхода кнопка браузера «назад» возвращает на страницу перед ошибкой.
- Запуск и продолжение переговоров сначала выполняют запрос к серверу. При неудаче перехода к диалогу нет; повторное нажатие не создаёт параллельные запросы.
- Удалены два встроенных демо: `new-deadline` и `feedback`. Новые установки их не создают; миграция скрывает прежние оригиналы без удаления версий и истории попыток. Пользовательские копии сохраняются.
- В профиле нет ссылок у записей истории и кнопки «Повторить» при недоступности истории.
- Кнопка смены пароля отключена до заполнения текущего пароля. Ошибки полей отображаются внутри формы; браузерные подсказки обязательного ввода отключены.
- Фото профиля загружается в настройках, отображается в профиле и меню аккаунта и сохраняется в БД. Допустимы PNG/JPEG/WebP до 5 МБ; клиент обрезает изображение по центру до 256 × 256 и удаляет метаданные при перекодировании. API принимает растровые data URL до 512 КБ. Фото можно удалить; при невозможности показать его остаются инициалы. Маленькая иконка поверх аватара убрана.
- Тема: системная, светлая, тёмная. Настройка доступна в шапке, включая конструктор и страницы ошибок, сохраняется в браузере. Системный режим реагирует на изменение настройки ОС. Тёмная палитра: зелёно-серые поверхности, светлый текст, шалфейные и коралловые акценты.

## Главный администратор

Поля `ADMIN_NAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` в серверном `.env` используются при первоначальном создании главного администратора. Пароль — от 8 до 128 символов.

После `npm run db:setup` этому аккаунту доступна страница `/admin/accounts` с формой создания администраторов. Требуются имя, почта и пароль. Создание другого аккаунта не меняет текущую сессию.

Права проверяет сервер. Обычный администратор может работать со своими сценариями, но не создавать администраторов. Поле `is_super_admin` закреплено за аккаунтом в БД, поэтому изменение почты главного администратора не передаёт его права пользователю со старым адресом. Повторный seed не сбрасывает пароль и не переопределяет существующего главного администратора.

Новые API:

| Метод и адрес              | Назначение                                          | Доступ                      |
| -------------------------- | --------------------------------------------------- | --------------------------- |
| `POST /api/admin/accounts` | Создать администратора: `name`, `email`, `password` | Главный администратор       |
| `PATCH /api/me/avatar`     | Сохранить `avatar` либо удалить с `avatar: null`    | Авторизованный пользователь |

## Конструктор

- Убраны раздел «Этапы», выбор этапа у реплики и подписи на карточках. Этапы и intent сохранены в модели для совместимости существующих документов; поле intent удалено из интерфейса.
- Отключены предупреждения браузера при перезагрузке и выходе к списку. Изменения по-прежнему синхронно сохраняются в `sessionStorage` и восстанавливаются при возвращении в той же вкладке. Серверное сохранение остаётся явным. При недоступности локального хранилища остаётся предупреждение внутри интерфейса.
- У стартовой реплики нет свободного входного порта. Существующие возвратные связи старых графов сохраняются, их входные точки скрыты и недоступны для новых соединений.
- Двойной клик по реакции открывает её в шторке и ставит фокус в поле названия. Подсветка последней реакции повторяет скругления карточки. Направление исходного порта учитывает положение связанного блока. Маршрутизация, подсветка связей и режим «Показать ветку» из v0.4.8 сохранены.
- В справке убран внутренний скролл. Все инструкции сохранены в переключаемых разделах «Полотно», «Связи», «Навигация» и «История»; на невысоких широких экранах текст организован в две колонки.
- Сохранён импорт/экспорт сценариев новой версии проекта: Arena JSON v1, прежний JSON черновика и definition schemaVersion 2. Инструменты JSON и новая справка поддерживают тёмную тему.
- Панель проверки изменяет ширину и высоту перетягиванием верхнего левого угла. Доступно управление стрелками клавиатуры; размер сохраняется и ограничивается размерами рабочей области.
- На кнопке создания сценария текст расположен перед стрелкой.

## Проверки

```bash
npm run build
npm run test:logic
npm run test:api:embedded
npm run test:ui:embedded
```

API-проверки используют изолированный PGlite; рабочая PostgreSQL не затрагивается.
Браузерные проверки охватывают историю 404/500, отсутствие сети, сохранение ответа при 500, профиль, аватар, права главного администратора, темы, восстановление черновика и изменение размеров панели проверки.
