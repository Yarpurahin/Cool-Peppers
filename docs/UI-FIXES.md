# Исправления интерфейса и управления доступом

Патч `cool-peppers-fixes.patch` подготовлен для архива `Cool-Peppers-develop.zip`, в котором уже применён перенос страниц «О проекте» и «Обратная связь».

## Применение

Из корня проекта:

```bash
git apply --check cool-peppers-fixes.patch
git apply cool-peppers-fixes.patch
npm run build
```

Перезапустите приложение. Новых зависимостей и миграций нет; миграции 001–005 не изменены. Коммит и push выполняются вручную.

## Интерфейс

- Выбор темы расположен справа в обычном хэдере и хэдере редактора. Меню оформлено для обеих тем; поддерживает стрелки, Home/End, Enter, Escape, Tab и закрытие кликом снаружи. Сохраняются системная тема по умолчанию, выбор в localStorage и синхронизация вкладок.
- Тёмная палитра использует Radix Colors 3: Gray Dark для фона, поверхностей, границ и текста; Green/Orange для фирменных акцентов. Фон `#111111`, поверхность `#191919`, основной текст `#eeeeee`, вторичный `#b4b4b4`, зелёный `#30a46c`, оранжевый `#f76b15`. Цвета собраны в `tokens.css`, новая UI-библиотека не подключается.
- «О проекте» — текстовая страница с описанием назначения, устройства и ограничений тренажёра. Иллюстрации, карточки и переходы к тренировкам из содержимого убраны. Ссылка на страницу остаётся в футере; в хэдере её нет.
- В форме обратной связи убран карандаш. Переиспользуемый `AccordionItem` плавно меняет реальную высоту ответа при открытии и закрытии, поэтому футер движется вместе со страницей. Закрытый ответ недоступен для фокуса; `prefers-reduced-motion` отключает движение.
- Во вкладке «Обращения» оформлены кнопки перехода и номер страницы, в том числе на узких экранах. Размер страницы и API обращений сохранены.
- Кнопки импорта и скачивания JSON используют одинаковое оформление. Техническая подпись о форматах убрана из интерфейса; поддержка форматов сохранена.
- Одиночный клик на реакции выделяет её, не раскрывая закрытую шторку. Двойной клик открывает редактирование и фокусирует название; Enter/Space делают это сразу. Если шторка уже открыта, одиночный клик обновляет её содержимое. Программное выделение ребра больше не раскрывает шторку между двумя кликами.

## Администраторы

Главный администратор видит список дополнительных администраторов: имя, email, дату создания и число доступных им сценариев. В список включены и ранее созданные аккаунты с ролью администратора. Уведомления о создании и снятии прав оформлены отдельной закрываемой плашкой.

«Удалить» открывает подтверждение снятия прав. Сервер в одной транзакции:

1. Проверяет полномочия и блокирует изменяемый аккаунт.
2. Меняет роль на обычного пользователя.
3. Передаёт главному администратору все сценарии, включая архивные и ранее удалённые; статус сценария не меняется.
4. Завершает все активные сеансы этого пользователя.

Аккаунт, пароль, аватар, попытки, ответы и отзывы сохраняются. После нового входа доступны обычные пользовательские функции. Опубликованные версии сценариев не переписываются. Главный администратор не может снять собственные права. Повтор запроса после потери ответа безопасен. Создание сценария и вход синхронизированы со снятием прав блокировкой аккаунта.

API:

- `GET /api/admin/accounts` — список, только для главного администратора; без паролей и хешей.
- `DELETE /api/admin/accounts/:id` — снятие прав, `204`; требует обычную защиту изменяющих запросов (`X-Arena-Request`, JSON, проверка Origin).
- `POST /api/admin/accounts` — прежнее создание нового аккаунта.

Email снятого администратора остаётся занят существующим аккаунтом. Повторное назначение прав и другие взаимодействия с дополнительными администраторами в этот патч не входят.

Ошибка снятия прав не закрывает подтверждение и не удаляет строку из списка. Общий попап ошибки остаётся единственным и доступен для закрытия даже поверх нативного модального окна.

## Проверки

```bash
npm run build
npm run test:logic
npm run test:api:embedded
# Linux/macOS; для PowerShell задайте $env:PGLITE_UI = "1" отдельно.
PGLITE_UI=1 npx playwright test tests/refinements.spec.ts tests/info-pages.spec.ts tests/reliability.spec.ts tests/interface.spec.ts tests/maker-editing.spec.ts
```

API-проверки проверяют права доступа, защиту главного администратора, повтор удаления, откат транзакции при ошибке, завершение нескольких сеансов, передачу сценариев, сохранность опубликованных версий и истории. PGlite проверяет SQL и поведение API, но не заменяет проверку конкурентных блокировок на рабочем PostgreSQL.

Браузерные проверки покрывают выбор темы, гидратацию готового HTML, мобильную вёрстку, открытие и закрытие FAQ вместе с футером, двойной клик по связанным и несвязанным реакциям, подтверждение и повтор снятия прав, пагинацию и прежние сценарии работы редактора.
