# Arena Scenario: portable format v2 / graph schema v3

Файл импортируется в разделе **Настройки → JSON сценария → Импортировать JSON**. Максимальный размер файла — 1,5 МБ.

## Корневая структура

```json
{
  "format": "arena-scenario",
  "formatVersion": 2,
  "definition": { "schemaVersion": 3 },
  "editor": { "positions": {}, "viewport": { "x": 0, "y": 0, "zoom": 1 } },
  "coverImage": null
}
```

`editor` и `coverImage` необязательны. При импорте `definition.metadata.id` и `definition.metadata.version` не заменяют ID и текущую версию существующего сценария.

## Реакции

Каноническая модель реакции намеренно хранит одну оценку — `penalty`:

```json
{
  "id": "reaction_example",
  "intent": "example_intent",
  "label": "Текст реакции",
  "examples": ["Пример свободной формулировки"],
  "nextNodeId": "next_node",
  "penalty": 1,
  "feedback": "Что в ответе было удачно или что можно улучшить."
}
```

Допустимы только три значения:

- `0` — **Уместная** реакция;
- `1` — **Сомнительная** реакция;
- `2` — **Нежелательная** реакция.

Не нужно хранить отдельный `grade`, `quality`, `criticalError` или другое поле оценки. Ровно одно из `nextNodeId` или `endingId` задаёт сюжетный переход.

## Досрочное завершение по ошибкам

```json
{
  "settings": {
    "allowRestart": true,
    "collectFeedback": true,
    "feedbackMode": "summary",
    "penalty": {
      "enabled": true,
      "threshold": 5,
      "failureEndingId": "ending-negotiation-failed"
    }
  }
}
```

`threshold` — накопленная сумма штрафов, при достижении которой используется общий отрицательный финал `failureEndingId`.

Порядок перехода после ответа:

1. К сумме добавляется `reaction.penalty`.
2. Если у реакции явно указан `endingId`, используется этот сюжетный финал.
3. Иначе, если включена penalty-механика и сумма достигла `threshold`, используется `settings.penalty.failureEndingId`.
4. Иначе выполняется `nextNodeId`.

Таким образом, специальный сюжетный финал имеет приоритет над общим финалом исчерпания лимита.

## Рекомендация порога в Maker

Maker анализирует только реально достижимые маршруты от `startNodeId`. Для каждого состояния учитываются узел и накопленная сумма штрафов. Это позволяет вычислять достижимые суммы без полного перебора всех комбинаций путей.

Анализатор определяет:

- минимальную и максимальную достижимую сумму;
- максимальную сумму, при которой общий penalty-финал ещё может реально сработать;
- достижимость выбранного `threshold`;
- наличие положительного penalty-цикла;
- возможность завершить сценарий одной реакцией;
- варианты **Строго / Рекомендуемый / Мягко**.

Ориентир около 65% от реально достижимого максимума используется только как стартовая точка. После этого порог проверяется на самом графе: должны существовать и нормальные завершения, и путь к penalty-финалу. Автор может задать значение вручную.

Если включён penalty-финал, но выбранный порог недостижим, публикация блокируется. Слишком строгий или слишком мягкий порог может давать предупреждение, но не блокирует публикацию, если логика остаётся достижимой.

## Остальные поля

`metadata`, `characters`, `stages`, `nodes`, `endings` сохраняют прежнее назначение. `feedbackMode` поддерживает `immediate`, `summary` и `hidden`.

## Совместимость

Импорт по-прежнему принимает старые Arena JSON / definition v2 с `reaction.evaluation`, `reaction.legacy`, `failureRule`, `legacyFailure` и загруженный переходный `penaltyRule`. На границе импорта они преобразуются в канонический `schemaVersion: 3`.

Новые экспорты создаются как `arena-scenario`, `formatVersion: 2`, `schemaVersion: 3`.
