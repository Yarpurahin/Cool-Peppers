# Arena Scenario JSON v1

Файл импортируется в разделе **Настройки → JSON сценария → Импортировать JSON**. Максимальный размер файла — 1,5 МБ.

## Корневая структура

```json
{
  "format": "arena-scenario",
  "formatVersion": 1,
  "definition": { "...": "MakerDefinition schemaVersion 2" },
  "editor": { "positions": {}, "viewport": { "x": 0, "y": 0, "zoom": 1 } },
  "coverImage": null
}
```

`editor` и `coverImage` необязательны. Если `editor` отсутствует, конструктор сам упорядочит блоки. Если `coverImage` отсутствует, текущая обложка не меняется. Значение `null` удаляет текущую обложку.

При импорте `definition.metadata.id` и `definition.metadata.version` из файла не заменяют идентификатор и текущую версию сценария в базе. Это позволяет безопасно переносить один JSON между разными черновиками.

## metadata

- `id` — технический ID. В импортируемом файле должен соответствовать формату `[a-zA-Z0-9_-]`, но при загрузке в существующий сценарий будет заменён его ID.
- `version` — положительное целое число; при публикации сервер назначает актуальную версию.
- `title` — название сценария.
- `description` — короткое описание.
- `category` — категория.
- `difficulty` — `easy`, `medium` или `hard`.
- `duration` — строка, например `5–10 минут`.
- `skill` — тренируемый навык.
- `context` — вводная ситуация.
- `goal` — цель участника.
- `playerRole` — роль участника.
- `tip` — совет перед началом.

## characters

Каждый персонаж имеет уникальный `id`, `name`, `initials`, `role` и `description`. Поле `characterId` реплики должно ссылаться на существующего персонажа.

## stages

Этап — необязательная логическая группа реплик. `stageId` реплики должен ссылаться на существующий этап. Само отсутствие `stageId` допустимо.

## nodes и reactions

`startNodeId` указывает на первую реплику. В каждой реплике:

- `id` — уникальный ID блока;
- `title` — внутреннее название;
- `characterId` — персонаж;
- `stageId` — этап, необязательно;
- `text` — текст персонажа;
- `reactions` — варианты реакции пользователя, максимум 30.

В реакции:

- `id` — уникальный ID;
- `intent` — латинские буквы, цифры и `_`, начинается с буквы; intent уникален внутри одной реплики;
- `label` — текст кнопки для участника;
- `examples` — примеры пользовательских формулировок;
- `evaluation` — учебная оценка реакции: `grade` (`strong`, `acceptable`, `weak`, `critical`), `penalty` и пояснение `feedback`;
- **ровно одно** из `nextNodeId` или `endingId` задаёт следующий шаг.

## endings

Финал содержит `id`, `title`, `description`, `type` (`success`, `neutral`, `failure`) и необязательный `nextStep`.

## settings

```json
{
  "allowRestart": true,
  "collectFeedback": true,
  "feedbackMode": "summary"
}
```

`feedbackMode`: `immediate` — показать оценку сразу после выбора, `summary` — только в итоговом разборе, `hidden` — не показывать оценку участнику. Необязательное `failureRule` сохраняет автоматическое завершение по порогу штрафов для сценариев, где такая механика нужна.

Импорт старых Arena JSON по-прежнему понимает `reaction.legacy` и `settings.legacyFailure`, но сразу преобразует их в текущую модель. Экспорт всегда создаёт только новый формат.

## Совместимость

Импорт также принимает:

1. JSON черновика из старых версий конструктора (`preview + definition + editor`).
2. Чистый объект `MakerDefinition` с `schemaVersion: 2` без оболочки `arena-scenario`.

Рекомендуемый формат для новых файлов — `arena-scenario` версии `1`.
